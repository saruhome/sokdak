# SokDak 장애·보안 사고 대응 절차

**문서 버전:** 1.0
**목적:** 서비스 중단, 계정 탈취, 개인정보 노출, 악성 UGC 확산, 결제·권한 오류에 대한 초기 대응을 표준화한다.

## 1. 심각도와 초기 목표

| 등급 | 예시 | 초기 목표 |
|---|---|---|
| SEV-1 | 개인정보·권한 우회, 대규모 데이터 노출, 계정 삭제 오작동, 서비스 전체 중단 | 인지 후 15분 이내 담당자 호출, 60분 이내 완화책 적용 |
| SEV-2 | 로그인·글쓰기·이미지 업로드의 광범위 실패, 긴급 유해 콘텐츠 확산 | 인지 후 60분 이내 조사·완화 착수 |
| SEV-3 | 단일 기능 오류, 제한된 사용자 영향, 일반 지원 이슈 | 다음 영업일 내 원인·수정 계획 수립 |

## 2. 공통 대응 절차

발견자는 발생 시각, 영향 범위, 재현 절차, 관련 사용자 ID·요청 ID·스크린샷을 사건 기록에 남긴다. 민감한 개인정보·비밀키·접근 토큰은 티켓·채팅·GitHub 이슈에 기록하지 않는다. 담당자는 영향 기능을 우선 차단 또는 숨기고, Supabase 로그·Auth 이벤트·배포 이력·최근 migration을 확인한다.

복구 전 변경은 최소 권한 원칙을 지키며, 데이터 수정·권한 완화·프로젝트 중지 같은 영향 큰 조치는 릴리스 담당자의 승인과 실행 기록을 남긴다. 복구 뒤에는 사용자 영향, 원인, 완화 시각, 재발 방지 조치, 추적 이슈를 정리한다.

## 3. 사건별 즉시 조치

| 사건 | 즉시 완화 | 후속 확인 |
|---|---|---|
| 계정 권한 우회 | 문제 RPC·Edge Function·RLS 정책 비활성화 또는 되돌림, 세션·키 회전 검토 | 보안 advisor, role별 재현, 감사 로그 |
| 개인정보 노출 | 공개 정책·뷰·버킷 접근을 즉시 제한, 노출 범위 보존 | 법적 통지 의무·영향 사용자·삭제/정정 조치 |
| 유해 UGC 확산 | 대상 콘텐츠 `hidden`, 반복 위반 계정·경로 제한 | 신고 큐, 차단·삭제 이력, 운영정책 개선 |
| 계정 삭제 실패 | 삭제 요청 기능을 일시 중단하고 고객지원 안내 | Auth·DB·Storage 정합성, 삭제 잔존 데이터 |
| Supabase 장애 | 상태 페이지·로그 확인, 기능별 오류 화면·재시도 제공 | 프로젝트 상태, rate limit, 복구 시점 |

## 4. 출시 전 필수 연결

출시 담당자는 크래시/JS 오류 수집 도구, Supabase Auth·DB·Edge Function 오류 확인 경로, 긴급 연락 채널, 롤백 대상 commit 및 배포 절차를 확정해야 한다. 이 저장소의 CI는 정적 검증을 자동화하지만, 실제 알림 대상·에스컬레이션 채널·온콜 담당자는 외부 서비스 설정이 필요하다.
