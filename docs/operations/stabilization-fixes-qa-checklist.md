# 안정화 작업 QA 체크리스트 (secureAuthStorage v2 / 계정 삭제 / 커뮤니티 페이지네이션)

이 세 항목은 각각 자동 회귀 테스트가 이미 있습니다(`__tests__/secure-auth-storage-test.ts`,
`__tests__/delete-account-edge-function-test.ts`, `__tests__/community-pagination-test.ts`).
이 문서는 Jest가 시뮬레이션할 수 없는, 실제 기기/실제 Supabase 백엔드에서만 확인 가능한
잔여 항목만 다룹니다.

## 1. secureAuthStorage v2 마이그레이션

**대상 빌드:** development build 또는 EAS build (Expo Go는 SecureStore 동작이 다를 수 있어 제외)

| 확인 항목 | 기대 결과 | 완료 |
|---|---|---|
| 기존(v1) 세션이 있는 상태에서 앱 업데이트 | 로그인 상태가 유지되고, 재로그인을 요구하지 않는다. | ☐ |
| 위 상태에서 앱을 한 번 더 재시작 | 여전히 로그인 상태가 유지된다(v2로 업그레이드된 뒤 정상적으로 계속 읽힌다). | ☐ |
| 완전히 새 설치(v1 세션 없음) | 정상 로그인·세션 저장·재시작 후 유지가 모두 동작한다. | ☐ |
| 기기 잠금 해제 없이 백그라운드에서 세션 접근 시도(가능한 경우) | `WHEN_UNLOCKED_THIS_DEVICE_ONLY` 설정대로 접근이 거부된다(기존 동작 그대로, 이번 변경으로 완화되지 않았는지 확인). | ☐ |

## 2. 계정 삭제 (delete-account Edge Function)

**주의:** 아래 항목은 실제 계정을 삭제합니다 — 반드시 테스트 계정으로만 수행하고, 운영 사용자 계정에는 실행하지 않습니다.

| 확인 항목 | 기대 결과 | 완료 |
|---|---|---|
| 게시글 이미지·프로필 사진이 있는 테스트 계정 삭제 | 정상 삭제되고, Supabase Storage에서 `post-images`/`profile-avatars`의 해당 유저 폴더가 비어 있다. | ☐ |
| 삭제 직후 같은 화면에서 재시도(더블 탭 등으로 유발) | 두 번째 요청도 에러 화면 없이 정상 처리되거나, 이미 로그아웃된 상태로 자연스럽게 전환된다(크래시·무한 로딩 없음). | ☐ |
| 삭제 후 같은 계정으로 로그인 시도 | 계정이 실제로 삭제되어 로그인할 수 없다. | ☐ |
| (선택, 별도 스크립트로 1000개 초과 객체를 미리 채운 테스트 계정) 계정 삭제 | 첫 요청에서 완료되거나, 완료되지 않았다는 명확한 안내 후 재시도 시 이어서 처리되어 결국 폴더가 완전히 빈다. | ☐ |

## 3. 커뮤니티 목록 페이지네이션 (차단 사용자 제외)

**준비:** 테스트 계정 A로 다른 계정 B를 차단한 뒤, B가 A가 보는 페이지 크기 이상 게시글을 작성한 상태를 만듭니다.

| 확인 항목 | 기대 결과 | 완료 |
|---|---|---|
| A 계정으로 커뮤니티 목록을 끝까지 스크롤 | B의 게시글은 전혀 보이지 않는다. | ☐ |
| 스크롤을 여러 번 반복(위아래로 오가며 `onEndReached` 재트리거) | 같은 게시글이 중복으로 나타나지 않는다. | ☐ |
| 차단하지 않은 계정으로 같은 목록 확인 | 모든 게시글이 정상적으로 보이고 "더 보기"가 매끄럽게 이어진다. | ☐ |
| 게시판 필터(궁금해요/Q&A/질문하기) 전환 후 스크롤 | 필터별로도 중복·누락 없이 정상 로드된다. | ☐ |
