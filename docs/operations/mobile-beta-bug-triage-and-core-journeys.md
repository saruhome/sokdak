# SokDak 비공개 베타 결함 이슈 트래킹·핵심 사용자 여정

이 문서는 [실기기 QA 체크리스트](./mobile-beta-device-qa-checklist.md)를 실행한 테스터가 결함을 재현 가능하게 남기고, 운영자가 Android 우선 비공개 베타에서 수정 우선순위를 일관되게 결정하기 위한 템플릿이다. 실제 개인 정보, 실사용 계정, 민감한 게시글, 인증 토큰, private 미디어 URL은 이슈에 포함하지 않는다.

## 1. 제출 전 판단 기준

테스터는 같은 문제를 이미 보고한 이슈가 있는지 먼저 검색한다. 동일한 원인의 현상이라면 새 이슈 대신 기존 이슈에 기기·OS·재현율·스크린샷을 추가한다. 앱이 멈추거나 개인정보가 노출될 가능성이 있으면 일반 채널에 올리지 말고 운영 담당자에게 즉시 P0로 전달한다.

| 결함 여부 | 보고 방법 |
| --- | --- |
| 기대한 흐름과 실제 결과가 다름 | 새 이슈 또는 기존 이슈에 재현 환경을 추가 |
| 언어·문구가 어색하지만 흐름은 진행됨 | P2 또는 P3 UX 이슈로 보고 |
| 정책·권리·요금처럼 앱 동작 외의 질문 | 결함이 아니라 운영 질문으로 분리 |
| 네트워크·권한 거부 후 복구가 안 됨 | 실패 화면과 재시도 단계까지 기록 |
| 이메일·토큰·전화번호·private URL 노출 의심 | P0로 즉시 보고하고 첨부 파일을 비공개 처리 |

## 2. 이슈 제목 규칙

제목은 검색 가능한 형식으로 쓴다.

> `[심각도][플랫폼][영역] 실제 문제 — 발생 조건`

| 좋은 제목 | 이유 |
| --- | --- |
| `[P0][Android][Auth] 로그아웃 뒤 이전 계정 아바타가 표시됨 — 앱 재실행` | 위험·기기·영역·재현 조건이 모두 있음 |
| `[P1][iOS][Voice] 음성 인식 권한 거부 뒤 설정 이동 버튼 무반응` | 권한 복구 흐름을 바로 식별 가능 |
| `[P2][All][Locale] 독일어 저장 버튼이 작은 화면에서 잘림` | 다국어·UI 조건을 좁힘 |

`안 돼요`, `버그`, `문제 있음`처럼 재현 조건이 없는 제목은 사용하지 않는다.

## 3. 복사해 사용할 이슈 템플릿

아래 블록을 GitHub Issue, Notion, Linear, Jira 또는 스프레드시트의 하나의 행에 그대로 사용한다.

```markdown
## 요약
[P?][플랫폼][영역] 실제 문제 — 발생 조건

## 환경
- 앱 버전 / 빌드:
- 플랫폼 / 기기:
- OS / 제조사 UI:
- 앱 언어:
- 네트워크:
- 계정 상태: 비로그인 / 신규 테스트 계정 / 기존 테스트 계정

## 사전 조건
- 예: 마이크 권한을 한 번 거부한 상태

## 재현 단계
1.
2.
3.

## 기대 결과

## 실제 결과

## 재현율
항상 / 간헐 / 1회 (시도 횟수: __회 중 __회)

## 영향
테스트가 막힌 기능, 사용자에게 보이는 데이터, 우회 방법 유무

## 증빙
- 개인정보·토큰·private URL을 가린 스크린샷 또는 영상:
- 발생 시각(시간대 포함):
- 로그 또는 추가 관찰:

## 제안 라벨
심각도 / 플랫폼 / 영역 / 언어 / 상태
```

## 4. 필수 필드와 라벨 체계

| 구분 | 값 | 사용 규칙 |
| --- | --- | --- |
| 심각도 | `P0`, `P1`, `P2`, `P3` | 사용자 영향과 우회 가능성으로 판단하며, 단순 불만의 크기로 판단하지 않음 |
| 플랫폼 | `android`, `ios`, `web`, `all` | 최소 하나 선택. 제조사·OS는 본문 환경에 별도 기재 |
| 영역 | `launch`, `auth`, `profile`, `search`, `voice`, `word`, `category`, `community`, `support`, `network`, `accessibility`, `localization` | 첫 증상 기준으로 하나를 우선 선택 |
| 언어 | `ko`, `en`, `ja`, `vi`, `es`, `de`, `n/a` | 번역·줄바꿈·검색 의미 일치 문제면 반드시 지정 |
| 재현율 | `always`, `intermittent`, `once`, `not-reproduced` | 운영자가 재현한 뒤 갱신 |
| 상태 | `new`, `triaged`, `planned`, `in-progress`, `fixed`, `ready-for-retest`, `verified`, `closed`, `duplicate`, `not-a-bug` | 테스트 종료 보고에는 `new`나 `triaged`를 남기지 않음 |

## 5. 심각도와 운영 처리 목표

| 심각도 | 판단 기준 | 초기 처리 | 종료 조건 |
| --- | --- | --- | --- |
| P0 | 앱 실행·인증·계정 격리·개인정보·회원탈퇴·핵심 학습 흐름이 막히거나 민감정보 노출 의심 | 즉시 운영 담당자에게 전달하고 추가 배포를 보류 | 수정 뒤 동일 기기·다른 조건에서 재검증 |
| P1 | 우회할 수 없는 주요 기능 실패, 반복 크래시, 음성 권한 복구 실패, 다국어 핵심 화면 심각한 깨짐 | 다음 수정 배치의 최우선 | 원인·수정 빌드·재테스트 결과 기록 |
| P2 | 우회 가능한 흐름 오류, 특정 기기 UI 깨짐, 번역 불일치 | 공개 출시 전 해결을 원칙으로 일정과 영향 검토 | 수정 또는 보류 사유 기록 |
| P3 | 경미한 간격·아이콘·표현·애니메이션 개선 | 백로그 등록 | 영향이 커질 때 재분류 |

## 6. 운영자 트리아지 절차

1. **비공개성 확인:** 첨부물에 개인 정보·토큰·private URL이 있으면 먼저 삭제 또는 비공개 처리한다.
2. **중복과 재현 확인:** 제목·영역·기기로 검색한 뒤, 다른 테스트 계정과 동일 환경에서 재현한다.
3. **심각도 확정:** 사용자 차단, 데이터·개인정보 위험, 우회 가능성, 재현율을 기준으로 P0–P3를 확정한다.
4. **담당·수정 빌드 지정:** 해결 책임자와 목표 빌드 번호를 기록한다. P0/P1은 수정 전후의 정책·권한·데이터 격리 영향을 함께 확인한다.
5. **독립 재검증:** 원 보고자 또는 다른 기기가 `ready-for-retest` 상태에서 동일 단계를 다시 수행한다.
6. **종료:** 결과·검증 기기·빌드 번호·남은 제약을 남기고 `verified` 또는 사유가 있는 `closed`로 변경한다.

## 7. 가장 크리티컬한 핵심 사용자 여정

아래 여정은 출시 가치와 개인정보 보호에 직접 연결되므로, 각 빌드에서 Android 대표 기기 최소 2종으로 먼저 검증한다. iOS 공개 전에는 iPhone에서도 같은 여정을 별도로 통과시킨다.

### CJ-01 — 비로그인 다국어 학습 발견

| 단계 | 테스터 행동 | 통과 기준 | 실패 시 심각도 |
| --- | --- | --- | --- |
| 1 | 앱을 새로 설치하고 비로그인으로 시작 | 홈·탭이 표시되고 로그인 강제가 없음 | P1 |
| 2 | 영어·일본어·베트남어·스페인어·독일어·로마자 키워드로 단어를 검색 | 관련 결과, 의미·예문·일치 근거가 자연스럽게 표시 | P1 |
| 3 | 없는 검색어와 카테고리 검색을 시도 | 짹이 빈 상태·재검색 경로가 표시되고 시드 이력이 보이지 않음 | P2 |
| 4 | 단어 상세의 TTS를 실행 | 재생·중지와 화면 복귀가 정상 | P1 |

### CJ-02 — 음성 검색 권한의 전체 수명주기

| 단계 | 테스터 행동 | 통과 기준 | 실패 시 심각도 |
| --- | --- | --- | --- |
| 1 | 검색 탭에서 처음으로 마이크를 누르고 권한을 허용 | 음성 인식 결과가 검색어·검색 결과로 이어짐 | P1 |
| 2 | 시스템 설정에서 권한을 거부한 상태로 재시도 | 거부 사유와 설정 이동·텍스트 검색 대안이 표시 | P1 |
| 3 | 음성 인식 중 백그라운드 전환·복귀 | 녹음 상태가 안전하게 정리되고 다시 시도 가능 | P1 |
| 4 | Android Pixel·Samsung 및 iPhone에서 반복 | 제조사·OS별 권한 UX 차이에도 앱이 멈추지 않음 | P1 |

### CJ-03 — 로그인·보안 세션·private 프로필 사진

| 단계 | 테스터 행동 | 통과 기준 | 실패 시 심각도 |
| --- | --- | --- | --- |
| 1 | 전용 테스트 계정으로 로그인하고 앱을 종료·재실행 | 세션 복구 또는 안전한 로그인 재안내 | P0 |
| 2 | 테스트 이미지를 프로필 사진으로 업로드 | 이미지 표시, public URL·저장 경로 노출 없음 | P0 |
| 3 | 앱을 5분 이상 백그라운드로 보냈다가 복귀 | 만료된 이미지로 깨지지 않고 갱신됨 | P1 |
| 4 | 로그아웃 후 다른 테스트 계정으로 로그인 | 이전 계정의 아바타·저장 데이터가 남지 않음 | P0 |

### CJ-04 — 저장 단어의 일관성·계정 격리

| 단계 | 테스터 행동 | 통과 기준 | 실패 시 심각도 |
| --- | --- | --- | --- |
| 1 | 단어 상세에서 저장·해제를 반복 | 즉시 일관된 UI 상태가 표시 | P1 |
| 2 | 저장 목록을 열고 앱 재시작 후 다시 확인 | 저장 순서·내용이 유지되고 목록이 정상 로드 | P1 |
| 3 | 다른 테스트 계정으로 로그인 | 첫 계정의 저장 단어가 표시되지 않음 | P0 |

### CJ-05 — 커뮤니티 온보딩과 안전한 참여

| 단계 | 테스터 행동 | 통과 기준 | 실패 시 심각도 |
| --- | --- | --- | --- |
| 1 | 비로그인으로 커뮤니티 탭 진입 | 안내 또는 읽기 흐름이 명확하고 하단 탐색 유지 | P2 |
| 2 | 로그인 뒤 정책 동의 | 필요한 동의가 1회 기록되고 흐름이 막히지 않음 | P1 |
| 3 | 전용 테스트 계정으로 게시글·댓글·좋아요·저장 | 데이터가 올바른 계정에만 반영되고 목록 갱신 정상 | P1 |
| 4 | 신고·차단 후 목록을 다시 확인 | 신고·차단 정보가 제3자에게 노출되지 않음 | P0 |

> **출시 전 전제 조건:** 정책 동의 원장은 검토된 버전별 정책 전문과 언어별 공개 URL·해시가 게시된 뒤에만 활성화한다. 현재 운영 DB에서 해당 원장 테이블이 배포되지 않았음을 확인했으므로, 법률 검토된 정책 전문 없이 동의 기록을 활성화하거나 통과 판정으로 처리하지 않는다.

### CJ-06 — 오류·네트워크 복구와 개인정보 최소화

| 단계 | 테스터 행동 | 통과 기준 | 실패 시 심각도 |
| --- | --- | --- | --- |
| 1 | 검색·저장·커뮤니티 로딩 중 오프라인 전환 | 이해 가능한 오류·재시도 경로, 앱 종료 없음 | P1 |
| 2 | Wi-Fi와 LTE/5G를 전환하며 목록·저장을 반복 | 중복·무한 로딩·저장 상태 역전 없음 | P1 |
| 3 | 권한 거부·잘못된 입력으로 오류 재현 | 오류 화면과 첨부물에 이메일·토큰·전화번호·private URL 없음 | P0 |

### CJ-07 — 계정 삭제와 데이터 정리

| 단계 | 테스터 행동 | 통과 기준 | 실패 시 심각도 |
| --- | --- | --- | --- |
| 1 | **전용 테스트 계정**에서 회원탈퇴 화면 진입 | 취소·확인·복구 불가 안내가 명확 | P1 |
| 2 | 탈퇴를 확정하고 재로그인 시도 | 세션·프로필 접근이 정리되고 의도된 안내가 표시 | P0 |
| 3 | 앱 재시작·커뮤니티·프로필 접근 확인 | 삭제 계정의 private 사진·개인 정보가 남지 않음 | P0 |

## 8. 베타 종료 보고 요약 표

| 지표 | 보고할 값 |
| --- | --- |
| 기기 커버리지 | Android/ iOS 기기 수, OS 버전, 제조사 UI |
| 핵심 여정 | CJ-01~CJ-07의 통과·실패·보류 수 |
| 결함 현황 | P0/P1/P2/P3별 신규·해결·미해결 수 |
| 재검증 | 빌드 번호, 검증 기기, 검증자, 결과 |
| 출시 차단 요인 | 미해결 P0, 데이터·권한 위험, 외부 의존 항목 |

비공개 베타 종료의 최소 조건은 **미해결 P0가 0건**이고, CJ-01부터 CJ-07까지가 Android 대표 기기에서 재현 가능하게 통과한 상태다. iOS 공개 전에는 같은 통과 기준을 iPhone 실기기에서 다시 적용한다.
